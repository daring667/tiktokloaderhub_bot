# Downloader Mini App Setup

The downloader Mini App is split into two processes:

- `docs/downloader.html` / `downloader.js` / `downloader.css` is the static Telegram UI.
- `api.server` is the private `aiohttp` API that validates Telegram `initData` and runs jobs.

## Local API

```bash
cd /home/droid/tiktokloaderhub_bot
MINIAPP_API_HOST=127.0.0.1 MINIAPP_API_PORT=8081 \
  venv/bin/python -m api.server
curl http://127.0.0.1:8081/api/health
```

The Mini App accepts the API URL as a query parameter, so a static page can be tested against
an API without rebuilding it:

```text
https://your-pages-host.example/downloader.html?api=https://api.example.com
```

The API requires the `X-Telegram-Init-Data` header generated by Telegram Web Apps. Do not use
an empty or fake value outside tests. `BOT_TOKEN` must be set in the API process environment.

## systemd

Install the API as a separate service after the bot's existing service:

```bash
sudo cp deploy/systemd/tiktokbot-api.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now tiktokbot-api.service
sudo systemctl status tiktokbot-api.service
curl http://127.0.0.1:8081/api/health
```

The API binds to `127.0.0.1` by default. Before exposing it to Telegram, put it behind an HTTPS
reverse proxy or Cloudflare Tunnel and set:

```bash
MINIAPP_API_HOST=127.0.0.1
MINIAPP_API_PORT=8081
MINIAPP_ALLOWED_ORIGIN=https://your-pages-host.example
```

Do not expose port 8081 directly to the public Internet. The API has owner-bound jobs, but HTTPS
is still required to protect Telegram `initData` in transit.

## Current MVP boundaries

- Supported UI platforms: TikTok and YouTube.
- One active job per Telegram user.
- Maximum result size: 50 MB.
- Job results expire after 30 minutes.
- Existing message-based bot downloads and Chaos Chain Mini App remain unchanged.
- The admin summary is read-only; service restart actions are deliberately not exposed yet.
